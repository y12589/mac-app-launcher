Mac App Launcher
======================

适用：macOS + Obsidian 桌面版（Intel / Apple Silicon）。
当前版本：1.7.5（作者：阎大大）。完整更新记录见 CHANGELOG.md。

本版重点：
1. 置顶应用直接显示在应用中心顶部“常用应用”区域，不创建置顶文件夹、分类或导航入口。
2. 置顶只是显示优先级，不改变应用原有分类；取消置顶后回到原分类和普通排序。
3. 拖动置顶卡片排序时，不改变软件原有分类。
4. 增加本机 Agent API：YOLO、Claude Code、Codex 或其他能调用本机 HTTP / curl 的 Agent，可查询已勾选应用并请求插件启动客户端。
5. API 只监听 127.0.0.1，并要求随机访问令牌；Agent 只能启动用户在插件中勾选展示的应用，不接受任意程序路径或 shell 命令。
6. 保留扫描、原生图标、分类、应用资料卡、编辑用途和一键启动。
7. 分类可自定义：新增、重命名（应用与归类规则自动同步）、删除（应用归入未分类）、上下排序，每个分类可配 emoji 图标，显示在分区标题与导航上。
8. 批量分类与归类学习：管理页每行可勾选，选中多个应用后一键设置分类；手动修改分类后按应用名记住规则，之后扫描与手动添加自动命中同类应用；拖拽到分类导航同样触发学习。管理页有“只看未分类”开关。
9. 拼音搜索：输入拼音首字母（如 wx）或全拼（如 weixin）即可匹配中文应用名；快速启动与应用中心搜索均生效。首次使用自动编译 Swift 转换组件（约几秒，之后毫秒级）。
10. 单应用快捷键：应用详情编辑模式可设置启动快捷键（如 Mod+Shift+1），即存即生效，也可在 Obsidian 快捷键设置中调整。
11. 场景模式：用批量勾选的应用一键创建场景（如“写作模式”）；快速启动面板可直接搜到场景并回车一键启动整组应用；场景启动 0.5 秒错峰逐个拉起，避免同时启动多个应用卡顿；管理页场景行可“关闭”场景，向场景内应用发送 macOS 原生退出指令（有未保存内容时应用会自行弹窗询问，不会强制 kill）；关闭场景按 bundle ID 匹配，中文名应用也能准确退出；设置页“常规”组可选择一个场景，打开 Obsidian 约 3 秒后自动拉起该场景，删除场景时自动清除该设置。
12. 最近启动：应用中心顶部新增“最近启动”区，显示最近使用的 8 个应用。
13. 应用详情为居中弹窗（带弹出动画），详情编辑模式可改介绍、用途与快捷键。
14. 设置页与自动更新：插件设置页可检查更新、一键覆盖更新，原应用数据 data.json 不丢；检查与下载失败（网络错误、超时等）自动重试最多 3 次；设置页可填“下载加速镜像”前缀，走镜像下载更新包，留空直连 GitHub；设置页“服务状态”行实时显示 Agent API 运行状态与监听端口；“关于”区显示当前版本与作者，提供 GitHub 仓库、更新日志、提交 Issue 入口。

升级：
推荐用设置页自动更新：打开插件设置 → 检查更新 → 按提示更新，data.json 与 icons 文件夹不受影响。
手动覆盖（备用）：
1. 完全退出 Obsidian（Cmd+Q）。
2. 解压 ZIP。
3. 用 mac-app-launcher 文件夹覆盖当前库的：
   .obsidian/plugins/mac-app-launcher/
4. 保留旧目录中的 data.json（不要删除），icons 文件夹也可保留。
5. 重新打开 Obsidian。
6. 打开“管理应用”，页面顶部会显示 Agent 启动接口、接口地址和访问令牌；管理页也可一键复制 Agent API 接入说明。

Agent API：
- Base URL: http://127.0.0.1:43171
  注意：若默认端口已被占用，插件会自动选一个可用端口；以 Obsidian 管理页面或设置页“服务状态”显示的端口为准。
- 所有 API（除健康检查）都要带请求头：
Authorization: Bearer <TOKEN>

1) 检查服务：
curl http://127.0.0.1:43171/v1/health

2) 查询已勾选、允许 Agent 启动的应用：
curl -H "Authorization: Bearer <TOKEN>" http://127.0.0.1:43171/v1/apps

3) 模糊查询（含拼音）与使用统计：
curl -H "Authorization: Bearer <TOKEN>" "http://127.0.0.1:43171/v1/apps?q=微信"

4) 查询分类：
curl -H "Authorization: Bearer <TOKEN>" http://127.0.0.1:43171/v1/categories

5) 启动应用（按准确名称匹配）：
curl -X POST http://127.0.0.1:43171/v1/launch \
  -H "Authorization: Bearer <TOKEN>" \
  -H "Content-Type: application/json" \
  -d '{"app":"ChatGPT"}'

也可以按应用 id 启动：
-d '{"id":"应用ID"}'

精确无果时自动模糊匹配；候选不唯一返回 409 及候选列表。

6) 批量启动（上限 20 个）：
curl -X POST http://127.0.0.1:43171/v1/launch-batch \
  -H "Authorization: Bearer <TOKEN>" \
  -H "Content-Type: application/json" \
  -d '{"names":["微信","飞书"]}'

Agent 推荐指令：
“当我要求打开某个 Mac 客户端时，先调用 Mac App Launcher 的 GET /v1/apps 查询允许启动的软件；如果用户指定的软件在列表中，调用 POST /v1/launch，传入精确 app 名称或 id。不要自行使用 open 命令或猜测应用路径。如果应用不在列表中，告诉我先在 Obsidian 插件里勾选该应用。”

安全：
- 服务仅绑定 127.0.0.1，不对局域网开放。
- 使用随机 Bearer Token 认证。
- Agent 仅能启动插件中已勾选的应用。
- 不支持任意路径、任意命令或远程主机控制。
- 在管理页面点击“重置访问令牌”可立即使旧令牌失效。
- 退出 Obsidian 后，本机 API 服务随插件停止。

应用中心：
- 点击应用卡片：打开介绍资料卡（居中弹窗）。
- 在资料卡点击“打开 XXX”：启动应用。
- 点击星标：将应用直接提升到页面顶部；取消星标后回到原分类。
- 拖动两个置顶应用之间的卡片：只调整置顶顺序，不改变分类。
- 拖动普通应用到另一个分类的卡片：移动到目标分类并调整顺序（同时触发归类学习）。
- 点击分类导航：筛选该分类；该分类中已置顶应用仍显示在内容顶部。
- 点击“编辑介绍”：自定义软件功能介绍和用途，还可设置启动快捷键。
- 顶部“最近启动”区：显示最近使用的 8 个应用。
- 搜索框支持拼音首字母与全拼。
- 快速启动面板：可直接搜到场景并回车一键启动整组应用。
